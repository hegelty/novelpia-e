# 노벨피아 e-ink UI 설계·휴리스틱 검토

**기준일: 2026-09-27.** 대상: 현재 `MainActivity`, `InkUi`, `PagedListView`, `KeyMappingDialog` 및 화면 조절 구현. 설계 기준은 [Shneiderman의 8가지 황금률](https://www.cs.umd.edu/~ben/goldenrules.html), 평가 항목은 [Nielsen Norman Group의 10가지 사용성 휴리스틱](https://www.nngroup.com/articles/ten-usability-heuristics/)이다. 아래 평가는 **코드·API 19 에뮬레이터 동작·합성 화면에 근거한 휴리스틱 검토**이며 사용자 연구, 접근성 인증, 실제 크레마 기기 검증이 아니다. 문서 초안은 코드 검토로 작성했고, 이후 통합 작업에서 아래 8개 이미지를 실제로 열어 배치·문자 표시·메뉴 중첩을 검토했다. 모든 화면 크기·글꼴 조건에서의 적합성을 의미하지 않는다.

## 설계: Shneiderman 8원칙 → 구현

| 원칙 | 현재 설계의 구체적 적용 |
|---|---|
| 일관성 | `InkUi`의 흑백 텍스트·버튼·초점/누름 상태, 48dp 버튼과 페이지형 목록·읽기 이동을 공통 패턴으로 사용한다. |
| 보편적 사용성 | 화면 버튼 외 물리 키 매핑, 읽기 글자 크기와 앱 화면의 소프트웨어 명도·대비·채도 조절을 제공한다. 기기별 키 코드·큰 시스템 글꼴의 효과는 별도 확인해야 한다. |
| 유익한 피드백 | 요청 중/완료/실패 상태 문구, 목록 범위와 읽기 진행, 키 학습 중 안내 및 제한 시간 표시가 있다. 전자잉크의 느린 갱신에서 지각되는 속도는 미검증이다. |
| 종료감을 주는 대화 | 설정은 적용/취소로 끝나며 목록의 첫·마지막 경계에서는 버튼 상태나 안내로 이동 완료를 알린다. |
| 오류 예방 | 비어 있는 로그인 입력에 오류·초점을 표시하고, 허용되지 않는 장 이동과 목록 경계 이동을 제한한다. 화면 조절의 ±는 범위 끝에서 비활성화한다. |
| 쉬운 취소 | 설정 변경은 적용 전까지 임시 상태이고 취소로 폐기한다. 키 학습은 뒤로/시간 초과로 중단하며, 뒤로 가기는 목록에서 앞 화면으로 돌아간다. |
| 사용자 주도 | 읽기 도구를 열고 닫고, 목록·장 이동과 물리 키 재지정, 새로고침을 직접 선택한다. 이메일 자동 로그인은 기본 끔이며 사용자가 선택하고 해제할 수 있다. |
| 단기 기억 부담 감소 | 화면에 제목·상태·목록 범위·읽기 진행을 표시하고 버튼에 동작명을 적는다. 복귀 시 목록 화면 위치와 읽기 진행 복원을 지원하지만 프로세스 종료 후 모든 상태의 영속성을 보장하지는 않는다. |

## Nielsen 10항목 점검

심각도는 이 문서만의 우선순위 판단: **0** 발견된 문제 없음, **1** 경미, **2** 개선 필요, **3** 주요 작업 방해 가능, **4** 작업 불가/심각한 피해 가능. 증거가 부족한 항목은 낮은 점수로 '통과' 처리하지 않고 **미검증**으로 적는다. 이 점수는 NN/g의 공식 인증이나 사용자 시험 결과가 아니다.

| 휴리스틱 | 근거·남은 위험 | 심각도 |
|---|---|---:|
| 1 시스템 상태 가시성 | 요청 상태, 목록 범위, 읽기 진행이 보인다. 실제 전자잉크의 갱신 지연에서 로딩 표기가 제때 보이는지 확인 필요. | 2 |
| 2 현실 세계와 일치 | `내서재`, `이어서 읽기`, `이전/다음` 등 작업 중심 한글을 사용한다. `화면 명도`는 화면 픽셀 변환이며 물리 조명 밝기가 아님을 설정에서 설명하지만 용어 혼동 가능성이 남는다. | 2 |
| 3 사용자 제어와 자유 | 설정의 취소·뒤로 이동·키 학습 취소가 있다. 페이지 넘김 중 외부 네트워크 요청은 진행 후 즉시 되돌림 여부를 실제 흐름에서 점검할 것. | 1 |
| 4 일관성과 표준 | `InkUi` 버튼과 우측 적용 행동, 공통 페이지 이동을 사용한다. 물리 키 초점 상태의 글자·배경 대비 문제를 수정하고 상태별 픽셀 검사도 추가했다. 기존 Android 시스템 대화상자는 앱 루트 색 필터 밖에서 중립적으로 남을 수 있다. | 1 |
| 5 오류 예방 | 빈 입력 검사, 비활성 경계 버튼, 키 학습 시 읽기 페이지 넘김 차단이 있다. 실제 크레마의 물리 키 코드/스캔 코드 충돌은 기기 시험 전까지 미확인. | 2 |
| 6 회상보다 인식 | 목록 위치·읽기 진행과 명시적 버튼 문구가 기억 부담을 낮춘다. 메뉴 안의 덜 자주 쓰는 기능 발견성은 사용자 관찰이 필요하다. | 2 |
| 7 유연성과 효율 | 물리 키와 화면 버튼, 글자 크기·화면 조절이 대안이다. 작은 화면/가로 방향/큰 시스템 글꼴에서 다이얼로그와 한 화면 목록의 수용량을 확인해야 한다. | 2 |
| 8 미니멀한 디자인 | 600×800 화면에서 제목·햄버거·진행률만 남긴 본문, 화면 단위 목록, 설정 패널의 문자 표시와 배치를 직접 확인했다. 중앙 탭으로 도구가 열려도 본문 영역·진행률이 변하지 않는 것을 검사했다. 최초 사용자에게 숨은 도구가 잘 발견되는지는 미검증. | 2 |
| 9 오류 인지·복구 | 실패 상태와 오류 대화상자에서 명시적 다시 시도/취소, 로그인 필요 시 로그인 이동을 제공한다. 새 UI에서 실제 계정 로그인 실패/복구 흐름은 아직 종단 검증 필요. | 3 |
| 10 도움말·문서 | 키 학습 취소 안내, 화면 조절의 조명 관련 설명이 있다. Google 계정 가져오기 절차·실패 시 안내는 해결되지 않은 범위이므로 배포 전 명확한 안내가 필요하다. | 2 |

## 실제 화면 검토

### 후속 사용성 수정 — 회차 의미·직접 동작·리더 복귀

- **실세계 대응/오류 예방:** 마지막 읽은 `EP.N`과 `등록 M편`을 분리했다.
  숫자가 같아도 다음화가 존재할 수 있으므로 숫자 비교로 완독 표시하지 않는다.
- **일관성/효율:** 원본의 선호작·알림·소장·최근 기록, 정렬·그룹·검색 구조를
  유지하고 행 오른쪽에 `이어보기`/`다음화`를 직접 노출한다. 제목 영역을
  누르면 이어보기·다음 회차·회차 목록 선택창을 연다. 상단 `내서재`는
  계정 관리창 대신 실제 서재를 연다.
- **상태 가시성:** 숨겨져 있던 목록 요청 상태를 표시한다. 리더의 마지막
  페이지는 문자 위치 백분율 대신 `마지막 페이지`로 표시하고, 유효 다음
  링크가 있을 때만 하단에 다음 회차 버튼을 노출한다. 자동 이동하지 않는다.
- **사용자 통제/기억 부담:** 리더 상단 `목록`으로 이전 회차 기록을 건너뛰어
  진입 목록의 서버 쪽·화면으로 돌아간다. 서재 URL의 정렬·그룹·검색 조건도
  그대로 사용한다. 목록이 서버에서 변경되면 없는 화면은 정상 범위로 보정된다.
- **미니멀리즘:** 리더 하단 탭 안내와 상단 사이트 홍보 접두사를 제거하고,
  작품명/회차 제목은 작은 두 줄로 표시한다. 서재 제목과 상세 정보의
  불필요한 간격도 축소했다.

남은 한계: 원본 웹의 표지·색상·모든 부가 기능을 복제한 UI는 아니다.
긴 제목은 줄임 표시될 수 있고, 실기기의 큰 시스템 글꼴·가로 화면·물리키/
잔상 및 실계정의 전체 로그인→독서→복귀는 별도 확인이 필요하다.

이후 사용자 피드백에 따라 홈의 홍보성 문구를 제거하고 앱 이름을
`노벨피아 e-ink`로 통일했다. 서재의 4탭·서버 정렬·그룹·검색과 마지막 읽은/전체
회차 표시를 추가했다. 저장 로그인은 기본 끔이며 명시적 선택·해제·삭제가 가능하다.
새 PNG `ui-library-sort.png`, `ui-library-empty.png`, `ui-sort-selector.png`,
`ui-login.png`와 갱신된 홈·최근 기록 화면을 직접 검토했다. 로그인 이미지는
빈 필드만 담았고, 합성 저장소의 암호화·설정 유지·삭제는 별도 동작 검사로 확인했다.
실계정의 자동 로그인 종단 동작은 추가 사용자 확인이 필요하다.

API 19 ARMv7 / 600×800 / mdpi에서 앱의 실제 `View`를 `Canvas`로 그려 PNG로 저장했다. 정적 디자인 목업이 아니며, OS의 전체 화면 캡처와도 구분한다. `FLAG_SECURE`는 유지했고, 서재는 합성 제목만, 본문은 자체 작성 샘플만 사용했다. 실계정 쿠키·작품 목록·유료 본문을 캡처하지 않았다.

시각 검토 과정에서 초안의 과도한 상단 테두리, 목록의 큰 행 간격, 설정 제목의 한글 누락·Holo 파란 선을 수정했다. 렌더 타이밍 때문에 독서 도구·마지막 목록을 제대로 담지 못하던 테스트 캡처도 레이아웃 완료 이후로 수정했다. 화면 이미지와 함께 중앙 탭·키 반복/UP·설정 취소/적용의 동작 검사를 수행한다. 최종 빌드별 테스트 수·서명·APK 해시는 `VALIDATION.md`에서 관리한다.

## 다음 검증 우선순위

1. **실제 크레마 장치:** 물리 키 코드·방향, 전자잉크 잔상/갱신 속도, 소프트웨어 필터의 성능·메모리·색상 효과를 측정한다. 화면 변환은 물리 프런트라이트나 하드웨어 EPD 설정이 아니다.
2. **레이아웃/읽기:** API 19의 작은 화면·가로 방향·큰 시스템 글꼴에서 버튼, 대화상자, 목록 페이지 수용량, 읽기 진행을 시각적으로 확인한다. 합성 PNG의 존재만으로 실제 기기 적합성을 주장하지 않는다.
3. **계정 종단 흐름:** 이전 네이티브 계정 파이프라인의 통과 기록을 **새 UI 로그인 검증 결과로 재사용하지 않는다**. 실제 로그인·서재·오류 복구와 Google 계정 가져오기 미해결 상태를 별도로 확인한다.
4. **검증 결과 분리:** 초기 UI 초안의 중간 결과는 최종 결과와 구분한다. 후속 수정의 빌드·스냅샷 검사 결과는 `VALIDATION.md`를 따른다. 과거 메모리 프로파일 측정 역시 새 화면 필터의 성능 측정값이 아니다. 휴리스틱별 위험 점수의 평균을 임의의 '사용성 합격 점수'로 사용하지 않는다.
